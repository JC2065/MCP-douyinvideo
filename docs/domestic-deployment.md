## 减少小程序重复提交的工作方式

1. 小程序保留原生交互、微信登录、媒体播放保存、权限提示、固定接口与配置结构。网站、中台、后端源码和凭据不打包进入小程序；目前主包约387.6KB，总包约5.2MB，案例分包仍保留。
2. 在广州开发验证后端修复、解析/转写稳定性、已有模型调用策略及归档；保持接口兼容。中台已有工具维护状态通过版本、冲突检查和回滚控制，客户端刷新后读取，服务器同时执行限制。
3. 后续优先扩展中台的提示词版本、模型策略、额度和归档健康面板，提供校验、发布预览、审计和回退；网站浏览版不优先优化。不能向小程序下发可执行代码，也不能用远程配置启用未审核的新业务。
4. 涉及原生页面、组件、微信能力/权限、新业务能力或客户端协议的改动，仍需正常提交审核。服务器部署不意味着免审，也不保证平台审核次数。
5. 模拟器默认也连接国内云端。仅需本机视频调试时，在开发者工具控制台设置 `wx.setStorageSync('youai.debug.local-backend', true)`；结束后 `wx.removeStorageSync('youai.debug.local-backend')` 并重新编译。此开关仅对devtools的视频接口有效；真机始终使用国内HTTPS，管理/同步/热点始终走云端。

飞书适合已有归档、检索和协作数据。实时账号、登录会话、权限、任务状态与配置事务继续保存在服务器数据库；云盘不是实时鉴权数据库，也不把私钥或访问令牌写入表格。既有归档队列负责上传、重试、SHA256校验和恢复；不要手工与队列同时处理同一作品。

回退时先核对当前版本和活动任务：恢复备份Compose到internal-api，再执行 `docker compose -f compose.video-cloud.yml up -d --no-deps --wait --pull never video`；恢复备份Nginx文件到sites-available/youai888，nginx -t通过后reload。原静态版本和数据均保留，不使用down -v，不回退数据库。客户端需要回退时使用本次提交的父版本；关闭云端地址切换不等于线上小程序自动回退。旧境外入口仅在域名白名单及真机验收通过、旧版本过渡完成后再单独退役。
