# 三分钟进度汇报规范

本规范用于所有需要持续执行的 YOUAI 任务，避免长时间无反馈。它约束协作过程，不改变任务范围、测试要求或完成标准。

## 时间规则

从最近一次用户可见的进度消息开始计时。只要任务仍在执行，每 3 分钟至少汇报一次；工具调用、构建、部署、上传、远程命令、测试和外部审批等待都计入时间。任务在 3 分钟内完成时，直接交付结果即可。

不能因为命令仍在运行而静默。无法安全中断的操作继续运行，同时按时说明正在等待的命令、已持续多久，以及是否收到输出。用户的新消息优先响应，然后继续原任务。

## 固定内容

每次状态只写四项，保持简短且可核验：

- 已完成：本周期得到的结果或证据；没有则写“暂无新结果”。
- 正在执行：当前唯一主要动作。
- 卡点：错误、外部依赖或“无”；不要把普通执行过程虚构成卡点。
- 下一步：当前动作完成后立即做什么。

示例：`已完成：镜像构建通过。正在执行：上传广州服务器，已传输 62%。卡点：无。下一步：加载镜像并检查 health。`

## 异常与等待

- 终端或工具超过 3 分钟没有输出：汇报“仍在运行/无新输出”，并说明是否可以并行做其他检查。
- 工具会话丢失或返回未知进程：立即确认远端实际状态，不反复轮询失效会话。
- 需要用户输入、扫码或人工审批：先完成所有不依赖该输入的工作，再明确说明只剩哪一步以及用户要做什么。
- 发现方向错误或范围扩大：立即报告原因和修正后的路径，不等到最终交付。

## 完成标准

最后一次汇报必须给出结果、测试或现场证据、Git commit，以及仍未验证的边界。没有真实证据时不得写“已完成”。进度汇报本身不计为代码改动，也不能替代 `docs/test-batches.md` 的批次记录。
