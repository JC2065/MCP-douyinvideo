# YOUAI 网页版设计方案

版本：0.1 · 日期：2026-10-10 · 依据：Demo 1.0 与当前创作者优先产品方案。

可运行的静态交互原型位于 [web/index.html](../web/index.html)。原型用于确认信息架构、响应式布局与交互方向，数据仍是本机演示内容，不能当作数据中台已经接通。

## 1. 小程序和网页端是否共用一个前端

结论是：**共享前端业务核心，分别实现展示层。**

当前小程序使用原生 WXML、WXSS 和 `wx.*` API，浏览器使用 HTML、CSS、DOM、History、文件与网络 API。强行让两端共用页面代码，会引入运行时适配层，增加包体、调试难度和平台兼容问题，也会迫使桌面网页沿用手机单列交互。

| 层次 | 是否共用 | 实现方式 |
| --- | --- | --- |
| 数据中台、数据库和文件服务 | 共用 | 同一套 `/api/v1` HTTPS 接口 |
| API 类型、错误码、数据模型 | 共用 | 独立 `shared` 包或从 OpenAPI 生成 |
| 校验、格式化、创作规则、同步队列 | 尽量共用 | 不引用 `wx`、DOM 或 Node 专属 API 的纯 JavaScript/TypeScript |
| 登录、存储、上传和系统能力 | 共享接口，分平台适配 | `wechat-adapter`、`web-adapter`、后续 `app-adapter` |
| 页面、导航、布局和组件 | 分开 | 小程序用 WXML/WXSS，Web 使用 Web 组件体系 |
| 视觉令牌与文案规范 | 共用 | 颜色、字号、间距、状态和动作名称由共享设计令牌约束 |

如果未来决定使用 Taro、uni-app 等跨端框架，应在真实登录、上传、长文本编辑、视频播放和桌面布局验证后再迁移。当前已经存在成熟原生小程序，直接重写会扩大风险，因此网页版先独立实现展示层更合适。

## 2. 网页版定位

网页版服务需要长时间整理内容、编辑脚本、比较案例和管理多个项目的创作者。它不是小程序的放大版：小程序强调随手记录和快速查看，网页强调并行信息、键盘编辑和持续工作。

网页版保持四个一级入口：灵感、创作、学习、我的。任务、商家、订单与金额能力不进入导航。

## 3. 视觉方向

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 雾蓝画布 | `#EAF1F8` | 页面背景，延续现有小程序冷蓝基调 |
| 纸面白 | `#FBFDFF` | 编辑与内容承载面 |
| 墨蓝 | `#172940` | 标题与正文 |
| YOUAI 蓝 | `#075DCC` | 主动作、选择与同步状态 |
| 明亮蓝 | `#1680F5` | 主按钮渐变起点 |
| 记忆绿 | `#43A184` | 品牌圆点及完成提示 |

字体采用 HarmonyOS Sans SC、苹方、思源黑体和微软雅黑的本机回退。标题使用紧凑字距和较高字重，正文控制在约 70 个中文字符以内。网页版不依赖远程字体，便于本地和内网环境调试。

桌面布局：

```text
┌──────────┬──────────────────────────────┬──────────────┐
│ YOUAI    │ 页面标题                      │ 今天         │
│ 灵感     │ 主要工作区                    │ 继续创作     │
│ 创作     │ 灵感输入 / 编辑 / 案例         │ 本周节奏     │
│ 学习     │                              │ 同步状态     │
│ 我的     │                              │              │
└──────────┴──────────────────────────────┴──────────────┘
```

1100px 以下收起右侧今日概览；760px 以下左侧导航转为底部四入口，内容回到单列。桌面主内容左对齐，右栏只放当前上下文，不重复一级功能。

视觉记忆点是灵感首页顶部的“灵感纸带”：左侧用一句明确的问题建立创作状态，右侧直接输入。其他区域减少装饰和同质卡片，主要依靠分栏、细线、色条与内容密度建立层级。

设计自检时删除了全屏统计数字、装饰性标签和每张卡片的悬浮动效；这些元素不能帮助创作者完成任务，也容易让产品变成通用 SaaS 模板。

## 4. 页面映射

| 小程序现有能力 | 网页版位置 | 网页端调整 |
| --- | --- | --- |
| 快速记灵感 | 灵感页顶部纸带 | 支持键盘连续录入，保存后留在当前页 |
| 点子、作品、收藏、日历 | 灵感页记录区 | 桌面可并排显示记录和热点；日历后续作为切换视图 |
| 热点推荐 / AI 找热点 | 灵感页右侧内容栏 | 与用户主题并列展示，结果可直接创建项目 |
| 开始创作、创作口令 | 创作页起点 | 合并为空白主题、学习方法、已有素材三个入口 |
| 六个工具 | 创作页工具带 | 工具结果统一进入当前项目 |
| 我的创作 | 最近创作与项目列表 | 桌面使用列表，支持搜索、筛选和批量管理 |
| 每日一拆与案例列表 | 学习页 | 一个主案例加紧凑案例行，减少重复封面占用 |
| 我的与更多设置 | 我的页 | 分为内容管理、创作设置、数据与账户 |

## 5. 共享代码目录建议

```text
shared/
  contracts/       API 请求、响应和错误码
  domain/          灵感、项目、学习记录的纯业务规则
  sync/            幂等键、待同步操作和冲突模型
  validation/      字段、文件和配置校验
clients/
  miniprogram/      WXML/WXSS 页面和微信能力适配
  web/              Web 页面、路由和浏览器能力适配
  app/              后续 App 展示与系统能力适配
```

当前仓库无需立刻移动全部小程序文件。先抽取新开发的 API 客户端、数据模型和同步规则，等灵感链路跑通后，再逐步迁移现有 `utils` 中不依赖微信的模块。

## 6. 网页版实施顺序

1. 将静态原型转换为正式 Web 工程，建立共享设计令牌、路由、错误边界和 API 客户端。
2. 接入统一登录和 `/me`，验证 Web Cookie 会话、退出和跨设备撤销。
3. 接通灵感列表、创建、更新、删除及增量同步，与小程序做同账号交叉验证。
4. 接通创作项目、历史版本和长文本编辑，验证并发修改冲突。
5. 接通学习记录、“我的”设置、文件上传和工具任务。
6. 完成移动 Web、键盘操作、无障碍和真实浏览器兼容验证。

## 7. 当前原型验收范围

原型已覆盖四入口切换、响应式导航、灵感记录筛选、新增灵感的本页反馈、创作入口、六工具入口、学习案例和“我的”三类管理分组。工具、登录、保存与同步动作只展示待联调反馈，没有伪造服务成功。
