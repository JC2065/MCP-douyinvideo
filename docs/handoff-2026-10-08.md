## 追加：记录列表固定高度滚动（2026-10-09 凌晨）

用户要求：记录列表的长度固定成日历的高度，多余内容在固定高度内滑动。依据 apple-ui-design skill（HIG Layout）实现：

1. **固定视口**：记录列表（列表/日历两种模式下的记录卡）包进 `scroll-view.scroll-y`（`.record-scroll`），高度用 CSS 变量 `--record-panel-h: 527rpx`（= 日历卡实测 274px，模拟器 390px 宽下 1rpx=0.52px）。列表/日历切换时该区域等高，页面不跳动。
2. **滚动边缘渐隐（scroll edge effect）**：容器 `.record-panel` 相对定位，底部叠 `.record-fade` 渐变遮罩（52rpx，`pointer-events:none`，z-index:3），内容被平滑淡出而非生硬切断——对应 HIG「控件与内容分离，用 scroll edge effect 区分」。
3. **卡片内边距收紧**（16rpx 18rpx）、卡片间距 20rpx，适配小视口密度。
4. 空状态改在固定容器内显示（`.record-empty`），不再撑开页面。

注意：`--record-panel-h` 是按日历卡当前内容实测校准的；若日历板块结构变化（如增删摘要行），需重新实测日历高度并同步该变量。已知边界：6 行月份时日历卡会比 5 行高约 46px，此时刻列表仍为固定 274px——固定视口优先。

验证：56 项单测 + 模拟器 9 项点击回归全部通过；实测列表视口 274px = 日历卡 274px，6 条灵感内容总高 503px 确认可滚动。

## 修正：悬浮球拖拽不保存（2026-10-09 清晨，用户实测发现）

用户反馈拖动后位置没保存。根因（用组件 probe + moveTo 实证）：旧代码只在 movable-view change 事件 `source==='touch'` 时记录位置、且只在 touchend 时写存储；但**模拟器里拖拽产生的 change 事件 source 是空字符串**（moveTo 实测 30 个事件全为 ''），全部被过滤，touchend 在部分场景也不触发——保存链路完全断裂。修复：onMove 不再过滤 source，拖动过程中持续写存储（150ms 节流）；touchend 只负责吸附+终存，不触发也不影响保存；防误触返回从「仅横向 >8px」改为「任意方向 >6px」（竖拖不再误返回）。端到端验证：moveTo(230,460) → 存储 {230,460} → 换页球恢复 (230,555)。83 单测 + 三套回归全绿。调试技巧：selectComponent('.app-navigation') 可直调组件方法；MovableViewElement.moveTo 是自动化驱动 movable-view 的唯一有效方式。
