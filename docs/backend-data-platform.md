# YOUAI 多端数据中台设计

版本：0.1 · 日期：2026-10-10 · 目标：微信小程序先接入，同时兼容后续 Web 和 App。

2026-10-15补充：[统一账号与资产迁移方案](account-asset-system.md)核对当前微信媒体服务、本机内容与模板同步的实际边界，定义保留现有用户ID的账号映射、资产索引、换机、双账号迁移及服务器恢复步骤。该补充为设计，未执行生产账号迁移。

当前 Demo 字段到数据库的拆分、旧本机数据迁移和首批建表范围见 [Demo 后端数据设计基线](demo-backend-data-design.md)，机器可检查清单见 [demo-backend-data-model.json](demo-backend-data-model.json)。

## 1. 定位与边界

数据中台是所有客户端共用的账号、数据、文件和任务服务。微信小程序、Web、App 只实现各自界面和系统能力，不各建一套业务后端。

首阶段覆盖灵感、创作项目、版本、学习记录、用户设置、素材元数据和工具任务。商家、订单、金额、支付、结算和运营审批暂不建模。平台公共密钥、数据库连接及服务开关属于安全运维配置；用户自己的内容和设置继续在“小程序 → 我的”中管理。

## 2. 总体架构

```text
微信小程序        Web        iOS / Android
      \             |             /
       HTTPS JSON API / 文件直传
                  |
          API 网关与统一鉴权
                  |
  用户与身份  内容数据  同步  文件  工具任务
                  |
       PostgreSQL + 对象存储 + 任务队列
```

首版采用模块化单体服务，所有模块共用一次部署和一个 PostgreSQL 数据库。工具任务通过队列异步执行，素材放入兼容 S3 的对象存储。等真实流量和团队边界明确后再拆服务，当前不引入分布式事务和微服务复杂度。

## 3. 多端身份

统一用户表 `users` 与外部身份表 `user_identities` 分离：

| 客户端 | 首选登录 | 身份记录 |
| --- | --- | --- |
| 微信小程序 | `wx.login` 临时代码由服务端换取微信主体标识 | provider=`wechat-mini`，subject=openid；同时记录 unionid（可得时） |
| Web | 短信、邮箱或受支持的 OAuth/OIDC | provider=`phone` / `email` / `oidc` |
| App | 手机号或 OIDC；需要时接微信 App 登录 | provider=`phone` / `oidc` / `wechat-app` |

多个身份只有经过已登录验证和显式绑定才能指向同一 `user_id`。客户端不能提交或修改 `user_id`。访问令牌短期有效，刷新令牌按设备保存并可单独撤销；Web 优先使用 Secure、HttpOnly Cookie，小程序和 App 使用系统安全存储中的 Bearer Token。

所有请求带 `X-Client-Type`、`X-Client-Version`、`X-Request-Id`。客户端类型用于兼容性和观测，不参与用户授权判断。

## 4. 核心数据模型

所有用户数据表包含 `id`、`user_id`、`version`、`created_at`、`updated_at`、`deleted_at`。`version` 用于乐观并发，`deleted_at` 作为多端同步墓碑。

| 表 | 主要内容 | 关键关系 |
| --- | --- | --- |
| users | 统一用户、状态、展示资料 | 一名用户可绑定多个 identities |
| user_identities | 微信、手机、邮箱、OIDC 主体 | provider + subject 唯一 |
| sessions | 刷新会话、设备、撤销状态 | 只存令牌哈希 |
| ideas | 灵感正文、标签、来源、收藏 | 可关联一个来源项目或目标项目 |
| projects | 创作项目、标题、状态、来源 | 当前版本指向 project_versions |
| project_versions | 脚本、分镜和保存快照 | 只追加，不覆盖历史版本 |
| learning_records | 案例收藏、笔记、学习进度 | case_id 指向客户端共享案例标识 |
| user_settings | 创作档案、模型选择、通用设置 | 可拆 JSONB 分区，禁止保存明文密钥 |
| assets | 文件类型、大小、哈希、对象键、处理状态 | 可归入项目或工具结果 |
| tool_runs | 工具、输入、状态、结果和错误 | 锁定执行时配置版本，不复制密钥 |
| credential_refs | 加密后的个人接口凭据引用 | 与 user_id、工具及配置版本绑定 |
| change_log | 用户数据变更游标 | 提供增量拉取，不保存密钥或正文副本 |
| idempotency_keys | 写入去重键与响应摘要 | 按用户、资源和动作隔离 |

生产库使用 PostgreSQL 行级归属查询和服务层授权双重约束。对象存储使用私有桶和短时签名 URL；客户端不能凭对象键直接读取文件。

## 5. API 契约

统一前缀为 `/api/v1`，使用 JSON 和 UTF-8。路由清单保存在 [backend/contracts.js](../backend/contracts.js)。核心分组：

- `auth`：各端登录凭证换取统一会话、刷新、退出。
- `me`：当前用户及已绑定身份摘要。
- `ideas`、`projects`、`learning-records`、`settings`：资源读写。
- `assets`：申请上传、完成确认和删除。
- `tool-runs`：提交、查询和重试异步工具任务。
- `sync`：多设备批量提交操作及按游标拉取变化。

创建请求必须携带 `Idempotency-Key`；更新和删除携带当前 `version`。成功响应包含 `requestId`、`serverTime` 和数据版本。错误统一为：

```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "数据已在其他设备更新",
    "requestId": "req_xxx",
    "details": {}
  }
}
```

HTTP 状态遵循：400 参数错误、401 未登录、403 无权限、404 不存在或不允许感知、409 版本冲突、413 内容过大、429 频率限制、5xx 服务错误。对其他账号的数据统一返回 404，避免泄露其存在性。

## 6. 离线与多端同步

客户端维持本机仓库和待提交操作队列：

1. 用户操作先写本机，产生稳定实体 ID、幂等键和本机操作序号。
2. 有网络时按顺序调用 `/sync/operations`；服务端返回实体版本和用户变更游标。
3. 客户端使用 `/sync/changes?cursor=...` 拉取其他设备变化。
4. 未冲突的数据自动合并；同一实体版本冲突返回当前服务端副本，保留本机副本并让用户选择。
5. 删除作为墓碑参与同步，所有活跃设备确认或超过保留期后再物理清理。

小程序受存储和后台运行限制，进入前台、下拉刷新、保存完成及网络恢复时触发短批次同步。Web 可在页面活跃时同步，App 可使用系统允许的后台任务；三端不依赖长连接才能保证正确性。

## 7. 安全与可观测性

- 服务端从会话确定用户，对每次数据库查询强制加入 `user_id`。
- 个人凭据使用独立密钥加密，响应只返回掩码和配置版本；日志、变更流、作品及分析事件都不记录明文。
- 上传先校验类型和大小，再签发短时上传地址；完成后校验哈希并异步扫描。
- 按用户、设备和接口限流；工具执行使用配额，但首阶段不出现任何金额字段。
- 日志记录 request_id、user_id 的不可逆摘要、客户端类型、接口、耗时、状态码和错误码。
- 指标至少包含请求成功率、P95 延迟、同步积压、版本冲突、任务成功率、数据库连接和对象存储错误。

## 8. 部署环境

至少划分 local、staging、production。三套环境使用独立数据库、对象桶、微信配置和加密密钥。小程序只连接已加入微信合法域名的 HTTPS 地址；Web 配置精确 CORS 白名单；App 开启证书校验。数据库变更通过可回滚迁移执行，不直接在生产库手工改表。

首个可部署版本建议使用 Node.js LTS、PostgreSQL 16+、兼容 S3 的对象存储和 Redis 任务队列。当前仓库的 [data-service.js](../backend/data-service.js) 是无外部依赖的领域规则基线，用于先验证多端共享、账号隔离、幂等、版本冲突和增量同步；它不是生产数据库实现。

后端运行基座、容器边界、备份恢复目标及正式云迁移关卡见 [后端运行与云迁移设计](cloud-runtime-design.md)。当前仓库已提供健康检查、配置校验、PostgreSQL 迁移器和首批身份/灵感表，但尚未实现登录与灵感 HTTP 业务接口，也尚未部署到云环境。

## 9. 联调顺序

1. 启动 staging，完成微信登录换会话和 `/me`，验证非法 token、退出及多设备撤销。
2. 接通灵感的创建、修改、删除、列表及增量同步，验证断网恢复、重复请求和双账号隔离。
3. 接通创作项目与历史版本，验证小程序创建、Web 编辑、App 查看及版本冲突。
4. 接通学习收藏、笔记、用户设置和本机数据迁移。
5. 接通文件上传与工具任务，逐项验证真实输入、失败恢复、结果归属和清理。

每一项均覆盖微信开发者工具、至少一个真实微信设备、桌面/移动 Web 视口和 App 测试壳。首轮先测试 API 与本机仓库，不等所有客户端界面完成后再集中排错。

## 10. 当前可执行验证

运行：

```powershell
node --test tests/backend-data-platform.test.js
```

测试覆盖三类客户端共享同一账号数据、双账号隔离、客户端不能伪造归属或金额字段、创建重试去重、旧版本写入冲突、删除墓碑、增量游标分页和首阶段 API 边界。后续 PostgreSQL 实现必须复用这组行为合同。
