# 创作板块开发方案：低成本复刻爆款（v2 定稿）

> 状态：**方案已与用户逐条确认（2026-10-18），尚未开始写代码。** 本文是唯一的方向依据。
> 任何代理（Claude / Codex）接手时：先读 `AGENTS.md`、本文第 0 节与第 11 节进度表，再按里程碑顺序开发；每完成一项就更新第 11 节并按 AGENTS.md 记测试批次与台账。不要擅自改动第 1 节的已定决策；如需改动，先问用户。

## 0. 接手速读
- 产品目标：用户粘贴爆款链接 → AI 先看懂 → 用户确认 → 按用户认可的“拆解方案”拆解 → 产出（文字作品 / 创作包 / 1:1 复刻）→ 发布 → 回传数据复盘 → 全站汇总迭代。
- 成本原则：主路线每条视频模型费“几分钱”；CPU 能做的不用模型；高成本视频生成只走用户自备 Key（已上线，见 `docs/replica-byok.md`）。
- 第一期只做**抖音**；但链接识别要做成“平台 → 解析方案”的路由，方便后续加平台。
- 已有可复用：`scripts/watch-flow.py`（看视频、缓存、对话、简报）、`scripts/content-understanding.py`（WATCH_SYSTEM、宽松解析）、`scripts/usage-ledger.py`（用量/预算）、`scripts/platform-config.py`（`videoUnderstanding` 配置）、`scripts/user-profile.py`（个性化画像）、`utils/watch-page.js` + `pages/video`（理解卡/对话/简报界面）、`utils/analysis-templates.js` / `analysis-presets.js`（旧固定维度，迁移为内置方案）、提词器（`utils/tool-interfaces.js` teleprompter）、`scripts/replica.py`（自备 Key 1:1 复刻）。

## 1. 已定决策（用户确认，勿改）
1. 主路线是“拆解爆款要素 → 用户自己创作”；1:1 视频生成仅作高质量档，用户自备 Key 自付。
2. 拆解方案由用户与 AI 对话生成，不用固定类型限制模型；类型判断错误时，用户用自己的话告诉 AI，AI 据此**生成新的拆解类型/方案**。
3. **新类型与整段会话上报中台，关联账号，不做匿名化**（需在隐私指引告知，见第 9 节）。
4. 拆解方案在**确认卡**中显示，并给出**默认依据**；同类视频默认使用上次方案。
5. 确认卡**倒计时 8 秒**，无操作按默认开拆（带保护条件，见 3.4）。
6. 不做渐进展示；改为**分层问询**：第 1 次试探性问询（可跳过）→ 同一视频第 2 次提交追问更多 → 第 3 次起 AI 对话式往复问答。
7. 等待优化：**两次请求**——快看（帧数减为 1/5–1/20）先回复大致内容，细看出完整理解卡。
8. 粘贴链接时弹使用说明，三个按钮：**[上传原视频] [放弃查看] [我知道了]**；保留上传原视频入口。
9. 文字作品产出时**同时展示之前抽取的原内容**（原屏幕文字/台词），方便用户对比改写好坏。
10. 文字作品的“套版成片”为**可选**，用户可直接复制去发布。
11. 数据回传：原视频公开数据 + 用户作品 1–3 天数据（链接自动抓取 + 后台截图），配**激励机制**；**全站汇总**用于整体调优。
12. 第一期全部要做：理解卡、确认卡（倒计时与纠错）、通用方案与对话生成方案、文字路线与创作包、样片归纳、自动匹配学习、套版成片、数据回传与复盘、全站汇总、中台上报。第一期平台只做抖音。

## 2. 总流程
```
① 粘贴链接 → 使用说明（上传原视频 / 放弃查看 / 我知道了）→ 平台识别（规则）→ 解析下载
   或 上传原视频（跳过说明与解析）
② 并行两次请求：快看（~10s，大致内容）+ 细看（~70s，完整理解卡，全站缓存）
   等待中：基于快看的试探性问询（可跳过）；按作者/话题预选拆解方案
③ 确认卡（细看完成后）：我看到的是… ｜ 方案 + 默认依据 ｜ [✓ 对 8] [部分不对] [完全不对]
④ 拆解卡逐项出现；可边看边对话（仅本次 / 存到方案）
⑤ 产出：文字作品（含原文对比；可选套版成片）｜ 创作包 ｜ 1:1 复刻（自备 Key）
⑥ 发布包 → 发布 → 回传（激励）→ 复盘卡 → 写回 方案统计/要素统计/画像/全站汇总/中台
```

## 3. 各模块规格

### 3.1 使用说明框与平台识别
- 每次粘贴链接弹出（可勾选“7 天内不再提示”，本地存储，`youai-link-notice-v1`）。文案：
  > **使用说明**　链接解析仅用于你个人学习、分析爆款创作手法，YOUAI 不提供原视频的下载、保存或二次分发。请尊重原作者的著作权与肖像权，创作时请改写文案、使用自己的素材；因不当使用产生的法律责任由使用者自行承担。你也可以直接上传有权使用的视频。
  > **[上传原视频] [放弃查看] [我知道了]**
- 放弃查看：清空输入，不发请求。上传原视频：走 `wx.chooseMedia`（视频）上传流程（新增 `/references/upload`，与解析得到的素材同样入 `REFERENCE_ROOT` 并 `AUTH.claim`）。
- 平台识别（前端+后端同规则，`utils/link-platform.js` / `scripts/link-platform.py`）：返回 `{platform:'douyin'|'kuaishou'|'xiaohongshu'|'bilibili'|'unknown', parser:'douyin-v1'|null}`。第一期非抖音返回“暂只支持抖音，请上传原视频”。
- 解析结果额外保存：作者 ID/昵称、描述中的 #话题、发布时间、公开互动数（点赞/评论/转发/收藏）、作者粉丝数（如可得）、抓取时间。

### 3.2 两次请求（快看 + 细看）
- 快看 `video_glance`：新场景，默认 `qwen3.8-flash`；帧数 = `max(2, round(maxFrames/快看倍率))`，倍率中台可配 5–20（默认 10）；短边 360；不转写；只返回 `{overview(≤60字), type, tags[], confidence}`；超时 20s；结果按素材缓存。
- 细看：现有 `video_watch`（content-watch-4）扩展字段：
  - `type`、`tags[]`：自由文本（不限定枚举），用于匹配方案。
  - `valueSources`: `{text, performance, visual, knowledge, product}` 0–1 占比，用于推荐产出路线。
  - `onScreenText`: 由 **本地 OCR**（RapidOCR，onnxruntime，Apache-2.0；需改 Dockerfile RUN → 整包部署）提供 `[{start,end,text,box}]`，在帧差/文字变化处取帧识别；模型提示中作为上下文。
  - `confidence` 已有。
  - 版本号升为 `content-watch-5`，旧记录可读。
- 两次请求同时发出；快看完成即在页面显示“大致是…（完整理解中）”。

### 3.3 分层问询
- 计数键：`user + 素材 sha256`，7 天窗口，存 `watch.sqlite` 新表 `attempts(user, asset, count, last_at)`。
- 第 1 次：等待期间 1–3 个可跳过问题（想重点看什么 / 想做什么 / 能否出镜、在哪拍），选项+自由输入；不答按默认。
- 第 2 次：先问“上次哪里不满意？[理解][拆解][产出]”，再按所选环节追问 2–3 个具体问题（模型生成，基于上次结果）。
- 第 3 次起：AI 对话式往复问答（`video_chat` 场景扩展 `mode:'interview'`），AI 主动提问直到用户确认“就这样”，产出新的需求摘要后重新拆解与产出。轮数上限中台可配（默认 6）。
- 所有问答写入会话（第 8 节上报）。

### 3.4 确认卡、默认依据、8 秒倒计时
- 内容：理解概述 + 时间轴（每条可 ✗）+ 方案行 + 依据行 + 三按钮。
- 默认依据（按强到弱，取命中项显示）：同一作者；该方案被确认次数；话题/标签吻合数；类型吻合；均无则“通用方案（首次此类）”。依据强度 `strong|medium|weak`。
- 倒计时：默认 8 秒（中台可配 3–30）。仅当 依据=strong 且 理解 confidence ≥ 阈值（默认 0.7，可配）时启动；任何触摸/滚动/输入立即暂停；首次出现的类型不倒计时。开拆后拆解卡顶部保留“理解不对？”入口。
- 中台统计：倒计时自动开拆率、自动开拆后被纠正率。

### 3.5 纠错
| 错误 | 交互 | 实现 |
|---|---|---|
| 细节错 | 时间轴条目 ✗ → 就地改写 | 写入本次会话 `corrections[]`，随拆解提交；0 费用 |
| 意图/类型错 | 自由输入“这其实是…，重点在…” | 文本调用更新本次理解；同时生成**新拆解类型/草稿方案**（3.6）；上报中台 |
| 没看清 | 再仔细看一遍（可选时间段） | 指定区间加密抽帧/提高分辨率重看；声音相关走 `video_watch_deep`；每用户每视频 ≤2 次 |
| 完全没看懂 | 再仔细看一遍 / 我来描述 | “我来描述”跳过 AI 理解，用描述 + OCR + 转写拆解 |
- 纠正只作用于该用户本次，不改共享缓存；同一视频 ≥3 个用户同向纠正 → 缓存标记 `needsReview`，下次自动重看更新。

### 3.6 拆解方案
数据结构（SQLite `plans.sqlite`）：
```json
{"id":"…","owner":"user|builtin","name":"情侣日常反转剧情","fitFor":"自由文本","source":"chat|samples|fork|correction",
 "fields":[{"key":"twist","label":"反转点","ask":"在第几秒反转？靠什么？","format":"text|list|timeline|score|option",
            "needTime":true,"useIn":"script|shotlist|rhythm|checklist|brief|text"}],
 "match":{"authors":[],"types":[],"tags":[],"confirmed":0,"examples":[]},
 "version":3,"history":[…],"status":"draft|active"}
```
- 固定字段（不可删）：一句话定位、时间轴、能不能学（每要素 copyable 高/中/低 + 学法）。自定义字段 ≤12。
- 生成：对话描述；样片归纳（同一作者 3–5 条链接，逐条细看（缓存），归纳共同套路，每字段标注出现于几条样片）；复制修改（内置方案由旧 6 种维度迁移）；纠错生成（status=draft）。
- 自动匹配：作者完全相同=strong；类型+≥2 标签吻合且 confirmed≥2=strong；部分吻合=medium；其余 weak。用户保留结果（未换方案且进入产出）→ 写回 match（作者/类型/标签/样例，confirmed+1）；用户换方案 → 当前视频特征记到新方案，旧方案该特征权重下降。
- 版本：拆解中对话调整 → [仅本次] / [存到方案]（version+1，可回退）。
- 套用：一次文本调用（理解卡 + 纠正 + 方案字段 → 逐字段填写），不重看视频；缓存键 `素材+方案id+version+纠正哈希`；无此要素填“本视频没有”，禁止编造。

### 3.7 产出
按 `valueSources` 推荐，用户自选：
- **文字作品**：
  - 左右（窄屏为上下）对比：**原内容**（OCR 屏幕文字时间轴 + 语音转写摘要，标注“原文仅供对比学习，请勿直接发布”）↔ **改写**（保留句式/节奏/字数/情绪走向，不照搬）。
  - 另含 3 个标题、封面大字、话题；每条改写可单独重写/编辑；显示与原文相似度提示（相似度过高提示修改，避免被判搬运）。
  - 复制去发布；或【可选】套版成片：画面需求清单（每段要什么画面、几秒）→ 相册选视频 → 小程序内 `video` + 覆盖文字层实时预览改字（0 成本）→ 服务器 ffmpeg 合成（文字时间轴、淡入/逐字、按原节奏切换；字体思源黑体/阿里巴巴普惠体）；默认不带原音乐，提示发布时选抖音“同款音乐”。
- **创作包**：按用户条件生成 分镜脚本（每镜头 时长/景别/手机摆放/动作或台词/字幕/难度/替代方案）、文案、节奏卡（BPM/卡点/剪辑点）、准备清单；口播稿一键进提词器。
- **1:1 复刻**：跳转 `pages/replica`（已上线）。

### 3.8 发布包、数据回传、激励、复盘
- 发布包：标题、话题、封面（从用户素材选帧 + 封面大字）、一键复制。
- 回传：作品详情/日历中“回传数据”。贴回作品链接 → 第 1、3 天定时抓取公开数据；上传后台截图 → 视觉模型（`data_screenshot` 场景，flash）识别 播放/完播率/2 秒跳出/平均播放时长/涨粉 → 预填表单用户确认 → 保存数字，**截图识别后删除**。微信订阅消息在第 1、3 天提醒（需在小程序后台申请模板）。
- 激励（中台可配）：每回传 1 条赠拆解/创作次数；连续回传解锁“专属复盘报告”；累计满 N 条且全站数据充足解锁“发布前预估”。
- 复盘卡：主要与用户自身近 10 条中位数比较；与原视频只比互动率（互动/粉丝、按发布天数折算）；指标→要素映射（低 2 秒跳出/高完播→开头有效；高播放低互动→结尾引导弱；高收藏→信息价值高）；标注样本数与可信度；不承诺“必火”。
- 写回：方案统计、要素统计（用户级）、个性化画像（`user-profile.py` 新信号 `perf`）、全站汇总表（按方案/要素/类型）。

## 4. 中台（集中迭代）
- 新类型/会话上报：`reports.sqlite`（关联账号）：视频 sha、平台、理解卡、纠正原话、问询问答、生成的方案、产出路线、结果反馈。中台页面：列表、筛选、查看会话、聚类同类新类型、一键升级为内置方案。
- 质量看板：纠错率（按类型）、重复提交率（第 2/3 次触发率）、倒计时自动开拆后被纠正比例、转化漏斗（拆完→产出→发布→回传）、各路线占比、费用与缓存命中。
- 配置（`platform-config.py` 新 section `creationBoard`，版本化可回滚）：快看倍率、倒计时秒数与阈值、纠错次数上限、分层问询轮数、激励额度、相似度阈值、OCR 开关。

## 6. 提示词要点（实现时写入代码常量并版本化）
- 快看：只说看到什么，≤60 字，给 type/tags/confidence；不推断意图。
- 细看：沿用 WATCH_SYSTEM（简体中文、不照抄歌词/转写、不确定写 uncertainties），新增 type/tags/valueSources；OCR 文字作为上下文。
- 方案生成/归纳：输出字段定义 JSON；归纳必须写每字段“出现于 N/M 条样片”；只总结手法，不收录原话、口头禅、品牌元素。
- 拆解：逐字段填写；无则“本视频没有”；时间需在视频时长内。
- 文字改写：保留结构/节奏/字数/情绪，禁止连续照搬原文 ≥8 字；输出相似度自评。
- 问询：第 2 次针对不满意环节；第 3 次起主动提问、每轮 1–2 问。
- 截图识别：只读数字与指标名，不读其它内容。

## 7. 费用与限额（中台可调）
- 每条视频：快看 <¥0.01；细看 ≈¥0.01（全站缓存）；拆解 ≈¥0.01/次；问询/对话每轮 <¥0.01；截图识别 ≈¥0.01。OCR、套版成片、抓取仅 CPU。
- 沿用 usage-ledger 的每用户每日次数与全站每日预算；超额降级为本地分析并如实提示。

## 8. 会话上报内容
关联账号上报：用户 ID、视频 sha/平台/作者、快看与细看结果、纠正与问询原话、方案（含新生成类型）、产出路线、用户反馈与回传数据。不上报：后台截图原图（识别后删除）、API Key、手机号。

## 9. 合规与审核
- 隐私指引新增：会话内容、拆解方案、作品数据会与账号关联上传，用于改进服务与全站统计；后台截图仅用于识别数字、识别后删除。首次进入创作板块时告知。
- 小程序隐私协议（mp 后台“用户隐私保护指引”）同步：相册（选视频/保存）、选择视频/图片、订阅消息。
- 使用说明框（3.1）每次粘贴链接时显示；不提供原片下载与分发。
- 字体使用可商用免费字体；成片默认不带原音乐。

## 10. 测试与验收
- 每个里程碑：Python 单测（模型与网络全部 mock）、Node 页面/契约测试、开发者工具走查（mock 优先）；真实模型调用须用户同意。按 AGENTS.md 计批次。
- 体验验收：
  - 老用户同类视频：贴链接 → 1 次操作（或倒计时）→ ≤90 秒得到拆解卡与产出。
  - 新类型：≤3 次交互进入拆解。
  - 全程无 >10 秒无反馈等待（快看 ≤20 秒必须给出大致内容）。
  - 文字作品同时展示原内容与改写，相似度过高有提示。
  - 截图识别后原图不留存（测试校验文件已删除）。
