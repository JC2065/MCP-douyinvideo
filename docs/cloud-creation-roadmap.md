# YOUAI 云端创作与资产矩阵推进规划

版本：1.0 · 日期：2026-10-12 · 状态：商业版统一六表、本机自动同步与文件归档恢复已验收；百度云部署与正式手机验证未完成。

最新实现与证据见[资产闭环](asset-lifecycle.md)。正常生成已自动入队并完成飞书归档；真实样片原片、代表帧及成片等 9 文件下载校验恢复通过。飞书权限故障自动重试，在线资产保留。下方架构中的分组织方案为原规划，当前按用户决定全部六表统一放在商业标准版组织。下一主线是服务器部署、HTTPS 合法域名与正式手机实测。

## 1. 唯一主方向

让创作者从点子、抖音参考链接或模板口令开始，通过少量但有效的沟通与分镜确认，得到可播放、可保存、可发布的视频成片。AI 画面为主，纯文字视频为辅。每次创作留下可复用资产，通过用户明确反馈逐步提高下一次结果的匹配度。

本文件是现有 [开发主导方案](development-master-plan.md) 下的专项执行路线；产品范围继续遵循 [产品方案](product-plan.md)。近期优先级为：正式手机可用 → 任务与资产可靠 → 参考还原与用户预期 → 成本优化。商家、支付、撮合和其他客户端大规模扩展继续延期。

决策检查：每个新增任务至少解决可用性、生成质量、资产复用或成本中的一项；不能说明贡献的任务放入候选清单，不插入当前阶段。用户最新决定优先，范围变化须记录原因与受影响的验收项。

## 3. 架构与资产分工

微信小程序 → HTTPS 业务 API → PostgreSQL 与持久任务队列 → 视频处理 Worker / 解析器 / 第三方模型 → 对象存储 → 成片播放与保存。

飞书通过后台同步适配器接入，承担协作与归档；飞书故障或额度不足时，不阻塞生成和播放。2 核服务器初期最多同时执行一个转写/抽帧/转码重任务，模型生成使用第三方服务；实际吞吐以压测决定，不能直接按 CPU 配置承诺并发。

| 位置 | 保存内容 | 责任 |
| --- | --- | --- |
| PostgreSQL | 用户、权限、任务、作品、资产 ID、哈希、版本、位置和血缘 | 业务事实依据；飞书表格不是用户权限判断来源 |
| 对象存储 | 活跃参考素材、近期成片、封面和需要模型访问的媒体 | 私有文件、短时签名地址；小程序和模型直接读取，减少服务器转发 |
| 企业飞书 | 作品总表、创作方案、反馈、费用、资源池看板 | 管理总台与团队协作 |
| 商业标准版飞书 | 原片、历史成片、资产包及归档/恢复索引 | 主要低频归档池；独立应用和凭据 |
| 服务器磁盘 | 下载、抽帧、音频与上传临时文件 | 有容量上限与清理策略，不能作为唯一长期副本 |

飞书大容量不能等同公开视频 CDN；临时链接、权限、Range 播放与模型拉取均须实测。云盘存储先验证容量、文件大小、分片上传和下载能力再启用自动归档。

| 表 | 最少字段 | 首批归属 |

| 资产目录 | 资产 ID、SHA-256、类型、字节数、来源资产 ID、存储池 ID、文件标识、引用数、校验状态 | 商业版为归档明细；数据库持有完整目录，企业同步摘要 |

## 5. 分阶段推进与验收

| 阶段 | 工作包与产物 | 完成条件 |
| --- | --- | --- |
| P0 上线准备（当前下一步） | 云端只读盘点、域名/备案/HTTPS/微信域名清单、两组织额度台账；冻结部署版本并准备回滚包 | 登录方式与依赖齐全；不覆盖服务器既有服务；部署清单可执行 |
| P1 手机云端闭环（最高优先） | API、数据库迁移、解析器、视频 Worker、HTTPS、对象存储、环境地址区分、用户鉴权与资产隔离 | 正式域名检查开启；手机移动网络从三种入口生成、播放、保存；重启后历史仍可访问；两个账号资产隔离 |
| P2 任务与资产可靠性 | 持久任务、幂等请求、费用任务防重复、阶段进度、超时/失败恢复、备份与恢复演练 | 断网/重启可重查任务，重复点击不重复收费；文件 SHA 校验；恢复演练通过 |

| P4 参考质量与沟通 | 多模态画面/字幕/音轨证据、镜头分段、可编辑故事板、参考素材预览、实际模型载荷复核 | 有固定样片集，分别比较主体/场景/动作/节奏/文案；缺证据不编造；用户确认后才付费生成 |
| P5 复用与偏好学习 | 模板、素材复用、局部重做、用户反馈与可编辑偏好、费用效果对比 | 用户可确认/撤销偏好；同源分析不重复收费；重做可追溯；匹配度与单次成本有真实基线 |

## 6. 归档、成本与失败规则

- 初始建议：近期作品在线保留 30 天；之后只有不被活跃任务引用且可成功恢复的资产才允许归档。用户保留设置优先。
- 归档顺序：写目标 → 校验 → 登记位置与血缘 → 恢复抽检 → 才允许清理在线副本。归档不等同备份，多副本要求另行配置。
- SHA-256 去重；方案版本与文件引用独立。删除前检查用户归属、引用与恢复机制，不能用移除列表代替删除资产。
- 使用事件触发和批量同步，不每秒更新飞书进度；token 缓存、指数退避、接口频率限制、失败队列、额度熔断必须覆盖。
- 套餐到期提前 60/30/7 天提醒；到期策略未确认前停止依赖新增权益的扩张，准备导出/迁移。
- 每条作品记录模型费用、处理耗时、资产大小、取回次数与流量；模型费用未知时写未知，不写 0。免费空间不能抵消取回流量与运维成本。

## 7. 防止方向丢失与 Agent 交接

每次任务开始：阅读本规划、[任务台账](task-ledger.md)、[测试批次](test-batches.md)、[交接说明](agent-handoff-2026-10-11.md)；检查 Git 状态，登记任务 ID、起始提交、所属阶段、目标、范围、验收和阻塞。

每次任务结束：登记变更与 commit、测试命令和结果、真实环境证据、未完成项、凭据位置（不含值）、下一条可执行操作。明确区分本机通过、云端通过、手机正式版通过。

测试遵循 AGENTS.md：每项关联测试，第 5 次汇总范围，第 10 次完整测试；修复重试不重复计数。当前累计第 50 次完整测试已通过，代码质量面板最终状态仍待确认，不能自行关闭该历史待验证项。

规划状态必须使用：未开始 / 进行中 / 待外部条件 / 待验证 / 已完成。任何已完成项都必须能指向提交和验收证据。每次交接注明当前主线，不只罗列最后修改的文件。
