## 核心用户流程

### 记录点子与创作方案

输入点子 → 记下来 → 本机记录列表/日历 → 开始创作或生成视频。
方案编辑与视频生成是不同结果：编辑文本不能展示「视频已生成」。作品版本、收藏和本机历史需有可识别的类型。首页切换 tab 与内部 view 不一定产生新路由，返回优先退出内部视图。

### 点子变视频

1. `idea`：选择点子、参考视频或口令；输入内容，可应用当前创作偏好。切换来源清理旧参考状态。
2. 参考视频专属：识别链接 → 平台解析 → 下载素材 → 校验视频；取得文件后再进行画面/音轨/结构分析。早期阶段提示按耗时估计，不能画成后台精确百分比。
3. `interview`：确认受众、目标、风格、时长、生成模式等；本次选择优先于档案。高度参考通道未就绪时不可选；首尾帧模式需要有效原片。
4. `storyboard`：生成并审阅分镜，允许修改；明确确认后才提交生成。不要让视觉改动跳过此确认。
5. `generating`：显示阶段、等待时间、服务状态；禁止重复提交。失败保留错误和可重试入口，不能假装已取消后台任务。
6. `result`：播放、保存到相册、查看资产/历史及反馈相关入口；生成成功与下载成功分开反馈。

视觉注意：当前模板的顶部「1/4」文案位于状态分支之外，可能与后续阶段标签并存；重设计时统一为单一准确步骤标题。生成中、成功、失败要分别出稿，不能只设计默认首页。

### 六类工具

| 工具 | 输入/处理 | 成功反馈与下一动作 | 必须保留的异常 |
| --- | --- | --- | --- |
| 视频下载 | 抖音分享文本/链接 → 解析与校验 | 播放 → 保存相册 | 无效链接、解析失败、下载失败、相册拒绝 |
| 文案提取 | 原片 → 云端语音识别 | 文本 → 复制；当前是展示文本，不是可编辑控件 | 服务不可用、繁忙、无人声；现 tiny 模型错字明显需校对 |
| 音频提取 | 原片 → 192kbps MP3 | 播放/暂停、时间 → 导出 MP3 到微信聊天 | 网络、存储、播放器错误、低版本不支持；取消分享不显示成功或失败告警 |
| 去水印 | 获取平台提供的无水印原片 | 播放/保存 | 不承诺涂抹任意水印；失败不能改成假的成功 |
| 封面提取 | 原片 → 代表帧 | 图片预览/保存相册 | 解码失败、下载失败、权限拒绝 |
| 提词器 | 手动输入/粘贴文本，本地运行 | 字号、速度、镜像、滚动/暂停、回到开头 | 空文本、离页计时清理；不声称云端同步 |

工具页面共用 run/copyText/saveAsset 等操作；音频另有 toggleAudio。音频「导出」不是保存到相册，也不是小程序沙盒保存成功提示。当前处理超时上限 180 秒，处理中显示耗时；不设计伪精确倒计时。

## 请求与界面响应约定

| 接口/动作 | 当前响应/机制 | 前端对应状态 |
| --- | --- | --- |
| POST /auth/login | 微信 code 换取 token/到期时间；客户端缓存，401 最多重登一次 | 登录/网络失败提示；凭据不进入界面 |
| GET /client-config | schemaVersion=1、revision、已知工具 maintenance | 启动刷新4秒超时、缓存1小时；不支持 schema 回退；维护工具提示稍后重试 |
| POST /tools/run | 同步结果 status=done，kind 为 video/audio/image/text；失败为 error | 按 kind 展示组件，不能把 HTTP 200 单独当业务成功 |
| POST /references/acquire | 素材元数据与 asset | 先文件校验成功，再开始分析 |
| POST /references/analyze、GET /reference-analyses/:id | 异步分析任务及状态 | 分析中/失败/完成；失败可重试 |
| POST /jobs、GET /jobs/:id | 视频生成任务及轮询 | generating → result 或错误；保留用户确认边界 |
| 媒体下载 | 带身份或短时签名的资源；Range 播放 | 206用于分段；完整下载成功后才调用保存/导出；不展示签名参数 |
| 资产与归档 | 云端资产/归档状态与本机历史分别存在 | 不混同「已生成」「已归档」「已保存手机」 |

详细字段以 scripts/video-server.py、utils/video-session.js、utils/video-service.js 为准，本文不另造一套协议。统一异步工具接口和通用结果组件仍是未来方案，未落地。

## 交互状态与视觉稿要求

每个交互至少标注：触发操作、即时反馈、等待反馈、成功结果、失败恢复、返回/离页后行为。每页按适用性覆盖默认、填充、空态、加载、禁用、错误、长内容、弹层；敏感设置需提供掩码态。

- 表单：输入内容保留；错误靠近相关区域；主按钮可点击范围明确，不仅用颜色表达状态。
- 列表：标题/来源/状态/操作层次分明，避免整卡与内部按钮的点击冲突。
- 弹层：说明关闭和确认的区别；删除本地记录有明确确认。
- 播放：音视频不与悬浮返回重叠；退出页面停止音频；保存失败能重试。
- 返回：顶部与悬浮返回复用 app-navigation。内部视图触发 back 事件；有路由栈则返回，否则回首页。拖动悬浮球不触发误返回。
- 适配：建议用 375px 代表稿并检查 320/390/430px；覆盖长中文、软键盘、刘海与底部安全区、大字号。尺寸是设计验收建议，不是当前全部已测试声明。
