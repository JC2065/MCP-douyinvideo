# YOUAI 产品方案

方案版本：0.3 · 更新日期：2026-10-10 · 状态：已确认多端数据中台方向。

执行优先级、功能状态与完成标准统一以[开发主导方案](development-master-plan.md)和[功能登记表](feature-registry.json)为准。

## 1. 当前产品方向

- 当前界面与交互以 **Demo 1.0** 为基线，标签为 `demo-v1.0`。基线提交：`c9a042646fa9936bf766e5277073dd3fad36a494`。
- 首阶段集中完善 **灵感、创作、学习** 三个业务板块；“我的”承载用户资料、内容管理和全部设置。
- 建设微信小程序、Web 和 App 共用的数据中台，统一负责身份、数据归属、持久化、同步、文件与工具任务；首阶段采用模块化单体，不建设商家运营后台。
- 商家、任务撮合、订单、预算、收益、结算、支付和提现全部搁置，不进入首阶段的数据模型与接口。
- 用户日常需要的配置和管理操作尽可能在小程序内完成；只有平台密钥、公共服务配置等安全运维项留在服务端部署配置中。

方案中的功能状态分为“当前已有”和“待实现”。待实现内容不能在界面上描述为已经上线。

## 2. 产品结构

| 板块 | 用户目标 | 首阶段核心能力 |
| --- | --- | --- |
| 灵感 | 随时记录并把想法推进到创作 | 快速记录、标签与搜索、收藏、日历、热点参考、带入创作、关联作品与复盘 |
| 创作 | 把想法或素材变成可继续使用的作品 | 创作项目、脚本与分镜、版本、素材、六个工具、AI 辅助、草稿与完成状态 |
| 学习 | 从案例中提取可复用方法 | 案例浏览、筛选、收藏、笔记、拆解、练习、带方法进入创作、学习进度 |
| 我的 | 管理个人内容和小程序设置 | 资料、创作档案、作品与草稿、收藏与笔记、工具/AI 配置、数据同步、隐私与通用设置 |

主导航不再承担商家任务和金额功能。现有 Demo 中的“任务”入口及相关本机流程只作为历史原型，后续应从首阶段产品入口移除；删除时另做代码改动和迁移验证。

## 3. 三个业务板块

### 3.1 灵感

灵感记录至少包含正文、创建时间、标签、来源、收藏状态和关联创作。用户可以按关键词、标签和日期查找，选择一条或多条灵感合并带入创作。创作完成后的复盘可以生成新灵感，并保留来源关系。

热点只提供参考内容及来源说明。没有在线热点服务时，应明确显示数据来源和更新时间，不能把本地样例写成实时榜单。

首批流程：记录想法 → 补充标签 → 收藏或带入创作 → 在作品中回看来源 → 复盘产生下一条灵感。

### 3.2 创作

“创作项目”是首阶段的核心数据容器，保存主题、脚本、分镜、版本、素材引用、灵感来源、学习案例来源和工具产物。AI 生成、文案提取、提词器或视频处理结果都归入对应项目，避免散落在不同页面。

首批能力按以下顺序完善：

1. 从灵感、空白主题或学习案例创建项目。
2. 生成并编辑脚本/分镜，保存草稿和历史版本。
3. 将工具结果保存到项目，并允许继续编辑或复制。
4. 标记完成，记录复盘，再生成新的灵感。
5. 页面关闭、网络中断或生成失败时保留用户已经输入的内容。

六个现有工具继续保留：视频下载、文案提取、音频提取、去水印、封面提取和提词器。提词器的基础滚动能力在本机运行；依赖外部服务的工具只有在真实接口接通并验证后才能标记可用。相关现状见[工具接口说明](tool-interfaces.md)和[视频服务说明](video-demo.md)。

| 工具 ID | 工具 | 归入创作项目的结果 |
| --- | --- | --- |
| download | 视频下载 | 视频文件与来源信息 |
| transcript | 文案提取 | 可编辑文本与可用的时间信息 |
| audio | 音频提取 | 可播放、可保存的音频文件 |
| eraser | 去水印 | 处理后的媒体文件及处理说明 |
| cover | 封面提取 | 图片文件与对应时间点 |
| teleprompter | 提词器 | 使用的脚本及本机阅读设置 |

### 3.3 学习

学习板块围绕“看懂—记录—练习—应用”组织，而不是只展示案例。每个案例应区分可核验事实、分析建议和练习模板。用户可以收藏案例、写笔记、标记学习进度，选择一种分析方法并带入自己的创作项目。

首批流程：筛选案例 → 查看拆解 → 收藏或记录笔记 → 选择可复用方法 → 填入自己的主题 → 创建创作项目。

现有案例和共享拆解实现分别见[主页面](../pages/main/index.wxml)、[案例页面](../case-study/index.wxml)和[拆解预设](../utils/analysis-presets.js)。

## 4. “我的”作为小程序内管理中心

“我的”不建设成平台运营后台，而是当前用户的管理中心。建议按使用频率分成四组：

| 分组 | 功能 | 说明 |
| --- | --- | --- |
| 内容管理 | 作品与草稿、灵感记录、收藏案例、学习笔记、工具产物 | 支持筛选、继续编辑、删除前确认和查看关联关系 |
| 创作设置 | 创作档案、默认风格、平台与时长、AI 模型、工具接口 | 默认值只辅助创作，本次输入可以覆盖 |
| 数据管理 | 登录与同步状态、本机数据迁移、导出、缓存与存储占用 | 同步失败保留本机数据；迁移必须由用户主动确认 |
| 账户与通用 | 头像昵称、隐私、授权管理、通知、外观、关于与反馈 | 设置保存后给出明确结果，敏感操作需要再次确认 |

常用内容管理入口直接展示，低频设置折叠在“更多设置”。平台公共接口对普通用户只读；个人接口允许在小程序中按工具配置。个人密钥提交后只回显掩码，不能写入日志或作品数据。现有配置页面见[创作偏好](creator-preferences.md)、[模型配置](ai-config.md)和[工具接口管理](tool-interfaces.md)。

平台公共密钥、数据库连接、服务域名白名单和平台级开关不提供给普通用户修改。这些属于数据中台的部署和安全配置，不在用户管理中心暴露。

## 5. 前端实现

小程序继续使用原生 WXML、WXSS 和 JavaScript。页面只负责展示与交互，业务数据通过统一的数据仓库和 API 层读写：

```text
页面 / 组件
    ↓
业务模块（灵感、创作项目、学习、我的）
    ↓
本机仓库 + 同步队列
    ↓
统一 API 客户端
    ↓
后端数据接口
```

每次保存先写本机并标记同步状态，再调用后端。成功后保存服务端版本号；失败时显示“待同步”并允许重试。创建操作使用客户端生成的稳定 ID 或幂等键，避免重复点击产生多条记录。登录切换时按账号隔离缓存，不能显示上一个账号的数据。

前端需要统一处理加载、空数据、保存中、待同步、失败、无权限和已删除状态。AI 或工具任务还需要排队中、处理中、成功、失败和已取消状态；离开页面后重新进入仍可查询结果。

## 6. 多端数据中台

后端首阶段采用模块化单体 API 服务、PostgreSQL 和对象存储部署。统一设计见[多端数据中台](backend-data-platform.md)。它负责：

- 验证微信登录会话并确定当前用户，不接受前端自行声明 ownerId。
- 对灵感、创作项目、版本、素材元数据、学习记录、用户设置执行增删改查。
- 校验数据归属、字段长度、状态变化和版本冲突。
- 接收增量同步请求，返回服务端版本与更新时间。
- 保存外部工具任务的状态和结果引用；文件本体存对象存储，数据库只保存元数据和权限关系。
- 加密保存个人接口凭据；公共接口凭据只存在服务端环境配置。

首阶段不提供商家、订单、金额、结算、平台运营工作台或通用审批流接口。

## 7. 首阶段数据模型

| 对象 | 关键字段 | 规则 |
| --- | --- | --- |
| users | id、微信主体标识、昵称、头像、状态、时间 | 微信主体标识唯一；注销流程后续补充 |
| user_settings | user_id、创作默认值、模型选择、通用设置、version | 每个用户独立；服务端返回可用配置，隐藏密钥 |
| ideas | id、user_id、正文、标签、来源、收藏、关联项目、version、时间 | 只允许本人读写；软删除便于同步 |
| projects | id、user_id、标题、状态、来源、当前版本、version、时间 | 草稿和完成状态都可恢复；来源关系可追踪 |
| project_versions | id、project_id、内容、分镜、创建时间 | 保存历史快照，不能随当前草稿覆盖 |
| assets | id、user_id、project_id、类型、文件引用、状态、时间 | 文件访问必须校验归属；删除要同步清理引用 |
| tool_runs | id、user_id、project_id、工具、输入引用、状态、结果引用、错误、时间 | 任务重进可查询；不复制接口密钥 |
| learning_records | id、user_id、case_id、收藏、笔记、进度、时间 | 案例内容与用户记录分开保存 |
| sync_changes | id、user_id、实体、实体 id、版本、操作、时间 | 用于增量同步和冲突排查，不保存正文副本 |

所有业务表都使用不可猜测的 ID，并包含 `user_id`、创建/更新时间和版本字段。金额字段、商家身份字段和订单状态不进入首阶段模型。

## 8. 接口边界

首批接口按资源组织：

- `/session`：微信登录换取会话、退出和当前用户。
- `/sync/pull`、`/sync/push`：按游标拉取变化、批量提交本机变化。
- `/ideas`：灵感查询、保存、删除、收藏和关联创作。
- `/projects`、`/projects/{id}/versions`：项目与版本管理。
- `/learning-records`：收藏、笔记和进度。
- `/assets`：上传授权、元数据和删除。
- `/tool-runs`：提交工具任务、查询状态和重试。
- `/settings`：用户可配置项；公共能力只返回可用状态，不返回平台密钥。

接口统一返回请求标识、服务端时间和最新版本。更新请求携带已知版本；版本冲突时保留两边内容，让用户选择，不能静默覆盖。

## 9. 实施顺序与验收

### M1：数据底座与灵感闭环

建立登录、用户归属、统一 API、本机仓库和同步队列；灵感完成云端保存、搜索、标签、收藏及带入创作。用两个账号验证数据隔离，并验证断网新增、恢复同步和重复提交。

### M2：创作项目闭环

将现有创作草稿、版本、工具结果和视频任务统一归入项目。完成“灵感/案例 → 项目 → 编辑版本 → 完成 → 复盘 → 新灵感”，验证失败不丢稿、重开可恢复和历史版本可追溯。

### M3：学习与“我的”管理

补齐学习笔记和进度同步；在“我的”提供内容管理、创作设置、数据管理及账户设置。验证用户可以只在小程序内完成正常使用所需的全部配置与管理操作。

### M4：真实工具逐项接入

根据已确认的服务协议接入工具。每个工具分别验证真实成功样本、失败样本、支持范围、结果保存和项目复用；不以模拟返回或任务编号作为成功验收。

首阶段完成条件：用户能在小程序中记录灵感、学习案例、创建并保存作品、管理个人内容和设置；跨设备重开后数据可恢复；两个账号互不可读写；整个流程没有商家或金额依赖。

## 10. 当前基线与迁移

Demo 1.0 当前已有本机灵感、创作、收藏、学习案例、工具配置与视频样例能力，也保留任务、身份切换和收益原型。后续实现时按以下原则迁移：

- 先为现有本机创作者数据增加稳定 ID 和归属，再接入同步。
- 用户首次登录后主动确认迁移；服务器核对成功前不删除本机数据。
- 将现有创作记录转换为项目及版本，将收藏转换为学习记录。
- 商家角色、任务和收益原型不上传到新后端；移除相关入口前保留本机数据，避免一次改动同时做不可逆清理。
- 每个阶段按[项目开发规则](../AGENTS.md)补充测试、验证和批次记录。

## 11. 暂缓事项
